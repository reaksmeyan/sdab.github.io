# Sdab: High-Fidelity UI Mockup Description

Covers Deliverable **6**. Unlike a typical mockup description, every screen referenced here is a **real screenshot of the built site**, captured headlessly at the stated viewport — not a rendering of an intended design. File paths point at the exact PNGs produced during QA; regenerate any of them by opening `index.html` (served over HTTP, not `file://`, so fonts and CORS behave correctly) in a browser at the given width.

---

## 1. Hero — desktop, dark mode (1440×900)

**What's on screen:** Sticky glass nav (logo, four links, theme toggle, filled "Get media" CTA) over a soft indigo/cyan grid-fade background with two large, slowly drifting blurred gradient blobs. Left column: bold two-line headline, a supporting sentence capped near 56 characters per line, the glass downloader form (URL field with a "Paste" affordance, primary "Get media" button showing a lock glyph, and the rights-confirmation row with its own lock icon and helper link), then four rounded "chip" highlights. Right column: a floating glass panel containing a gradient video-thumbnail mock with a play glyph and duration badge, a fake title/meta block, a progress bar, and three small floating glass badges ("MP4 · 1080p", "Ready to download", "Rights confirmed") that idle-bob at slightly offset speeds.

**Fidelity notes:** the lock icon on the submit button and the icon beside the checkbox are the *same* icon, reinforcing that ticking the box is what "unlocks" the action — confirmed working (icon swap on check) in `main.js`'s `rights.addEventListener`.

**Reference:** `/tmp/shot-desktop-dark-top.png` (regenerate via the QA script in the README).

## 2. Hero — desktop, light mode (1440×900)

Same structure, paper background, ink text, gradient blobs at lower opacity so they read as texture rather than dominate. The logo's gradient mark is fully visible here (fixed from an earlier bug where the icon `<svg>` sprite's `display:none` silently dropped its internal `<linearGradient>` in Chromium — the sprite is now hidden via absolute positioning + zero size + `overflow:hidden` instead, which preserves the gradient definitions).

**Reference:** `/tmp/shot-desktop-light-top.png`.

## 3. Preview card — "ready" state, light mode (1280×900, cropped)

Two-column card inside the glass shell: gradient thumbnail with a centered translucent play button and a duration badge (bottom-right), title, three meta rows (author/length/source, each with its own icon), and a green confirmation strip repeating that the user attested to their rights. Right column: two `fieldset`s (Format, Quality) built from **native radio inputs** styled as tiles — the selected tile gets a filled indigo tint and a 1px brand ring, not just a border color change, so the selection is legible even to users who have trouble distinguishing border shades. Below: estimated size, a full-width primary Download button plus a quiet "Start over," a progress bar (hidden until download starts), a status line, and — because this build ships in demo mode — an amber "Demo mode" note explaining that no real file is produced.

**Reference:** `/tmp/shot-ready-light.png`. Generated by driving the real form (`/tmp/flow.py`): typed a URL, checked the rights box, submitted, waited for the `ready` state — this is the actual DOM the JavaScript produces, not a static comp.

## 4. Full page, dark mode — sections 2–4 of 5 (1440×6500 full-page capture, sliced)

- **Feature bento:** one large gradient "Fast processing" card spanning 4 of 6 columns (with its own mini progress-bar illustration) beside five equal glass cards, each pairing a tinted icon badge with a heading and one sentence. No card uses an identical grey shadow — the hero card uses the brand-glow shadow, the rest use the standard glass shadow — so the eye correctly reads one as more important.
- **How it works:** three glass cards, each with a numbered circular badge overlapping the top edge and a small illustrative mock specific to that step (a typing cursor in a fake URL field; format pills with one active state; a progress bar), because the steps are a genuine sequence.
- **Download responsibly:** three border-left columns (green/red/indigo), each a short scannable list, sitting directly below "how it works" so the compliance framing arrives before the trust/comparison content, not buried at the bottom.
- **Why choose us:** a real `<table>` (not divs) with row and column headers, each cell pairing a check or × icon with text so meaning never depends on color alone. A caption line under the table hedges the comparison ("reflects common patterns… individual sites vary") rather than making unqualified claims about competitors.

**Reference:** `/tmp/full-dark-1.png`, `/tmp/full-dark-2.png` (see `07-Mobile-Design-Mockups.md` for the mobile equivalents).

## 5. FAQ, stats, and contact (dark mode)

Stats render as three large Poppins numerals in a divided glass strip, counting up from zero the first time they scroll into view (skipped entirely for users with reduced-motion preferences) — verified functional via `IntersectionObserver`. A caption directly beneath the numbers states plainly that they're sample figures for the preview, which is intentionally more visible than most sites make that kind of disclosure. The FAQ is a 4/8 split: heading and a "can't find yours" link on the left, eight native `<details>` accordion rows on the right, each opening with a rotating "+"→"×" glyph and a short answer. The contact section is a dark, rounded panel breaking from the light rhythm of the rest of the page — deliberately, since it's the one section asking for an action (get in touch) rather than presenting information.

**Reference:** `/tmp/full-dark-3.png`.

## 6. Design fidelity checks performed against this mockup

| Check | Method | Result |
|---|---|---|
| No horizontal scroll at any breakpoint | `document.documentElement.scrollWidth` vs `clientWidth` at 390/820/1280/1440px | 0px overflow at all four |
| No console errors / warnings | Playwright `console`/`pageerror` listeners across all breakpoints | Zero after fixing the `file://` CORS false-positive and the hidden-sprite gradient bug |
| Real functional states, not static comps | Automated flow driving the actual form (validation, DRM block, rights gate, preview, format switch, demo download, reset) | All 14 assertions passed — see `/tmp/flow.py` output captured during the build |
| Contrast | Programmatic WCAG luminance check on every text/background pairing used in the palette | All pairings actually used for text meet AA; the two ratios that don't (raw secondary/accent-500 on white) are only ever used as fills or icons on tinted chips, never as small text |
